2. Mount the form. The schema declares the inputs and the report; the transport is where submitted

   <Code code={quickStart} lang="ts" title="forecast-form.ts" />

3. Press **Run forecast**. MLForm validates both fields, calls `transport.submit` with the values,
   and renders the `forecast` report from the envelope the transport returns.

</Steps>

## What each part does

- **`id`** names the field or report inside MLForm. Layouts, errors, and `form.getField()` use it.
- **`mappedTo`** names the value for the model. The transport receives
  `request.modelValues` as `{ temperature: 21.5, humidity: 58 }`. A field without `mappedTo` sends
  nothing to the model. [Mental model](/getting-started/mental-model/#three-identities) explains why
  these are separate.
- **`min`, `max`, `required`** are checked before the transport runs. Invalid values never reach it.
- **The report envelope** `{ backend, mappedTo, status, payload }` tells MLForm which report the
  result belongs to. `backend: "default"` is the name used when you submit without naming a
  backend. The report with `mappedTo: "forecast"` receives `payload`, and the regressor renders
  its `value` with the configured unit and precision.

## Connect your backend

Replace the stand-in transport with a request to your service. Pass `request.signal` so MLForm can
cancel a stale request, and throw on failure so the form shows the error.

```ts title="transport.ts"
import type { Transport } from "mlform/transport";

export const transport: Transport = {
  async submit(request) {
    const response = await fetch("/api/forecast", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ inputs: request.modelValues }),
      signal: request.signal,
    });
    if (!response.ok) throw new Error(`Forecast failed with status ${response.status}.`);
    return response.json();
  },
};
```

[First backend](/getting-started/first-backend/) implements `/api/forecast` in Express and FastAPI.
